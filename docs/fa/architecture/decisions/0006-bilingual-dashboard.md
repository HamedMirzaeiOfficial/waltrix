# ADR 0006: داشبورد دوزبانه با متن انگلیسی به‌عنوان کلید

[English](../../../architecture/decisions/0006-bilingual-dashboard.md) · **فارسی**

**وضعیت:** پذیرفته‌شده

**زمینه.** داشبورد و مستندات باید به فارسی و انگلیسی قابل استفاده باشند. فارسی راست‌به‌چپ است، ارقام خودش را
دارد و معمولاً با تقویم شمسی خوانده می‌شود. داشبورد پول جابه‌جا می‌کند، پس بومی‌سازی هرگز نباید مبلغ را تغییر
دهد، و تغییر زبان هرگز نباید وضعیت عملیاتی را که نتیجه‌اش هنوز نامعلوم است از بین ببرد.

**تصمیم.**

* متن قابل ترجمه داخل `t("English text")` قرار می‌گیرد؛ متن انگلیسی خودش کلید است و
  `apps/web/src/locales/fa.json` ترجمه‌ی فارسی را نگه می‌دارد. رشته‌هایی که هنگام بارگذاری ماژول ساخته
  می‌شوند با `msg()` علامت می‌خورند و هنگام نمایش ترجمه می‌شوند. ترجمه‌ی جاافتاده به انگلیسیِ خوانا برمی‌گردد.
* زبان در `index.html` و قبل از بارگذاری React انتخاب می‌شود (انتخاب ذخیره‌شده، وگرنه زبان مرورگر) و
  `<html lang dir>` را تنظیم می‌کند. تغییر زبان، رابط کاربری را زیر کش React Query از نو mount می‌کند
  (`key={lang}`).
* تا وقتی یک عملیات پولی در جریان است یا نتیجه‌اش نامعلوم است، تغییر زبان رد می‌شود (`useLanguageLock`)،
  چون remount کلید idempotency‌ای را که صفحه برای بررسی نتیجه لازم دارد دور می‌اندازد.
* چیدمان از CSS منطقی استفاده می‌کند (`ps-*`، `text-start`، `end-*`)؛ مبلغ‌ها، شناسه‌ها و نام‌های لاتین به‌شکل
  متن چپ‌به‌راست ایزوله می‌شوند. عدد و تاریخ با `Intl` و `fa-IR` نمایش داده می‌شوند (ارقام فارسی، تقویم شمسی).
  مبلغی که با ارقام فارسی تایپ شده قبل از رسیدن به parser رشته‌ای SDK به ASCII تبدیل می‌شود.
* `scripts/i18n-check.mjs` در CI اجرا می‌شود و با ترجمه‌ی جاافتاده، ورودی غیرفارسی یا placeholder ناجور شکست
  می‌خورد.
* API انگلیسی می‌ماند. **کد** خطا قرارداد است و داشبورد با کد ترجمه می‌کند.

**ردشده.** کتابخانه‌ای مثل i18next یا FormatJS: توانمندتر است (جمع، پیام‌های ICU)، ولی فارسی این‌جا شکل جمعِ
مهمی ندارد و بقیه‌ی نیازها با `Intl` پوشش داده می‌شود. کلیدهای مات (`transfer.posted.title`): کلید ترجمه‌نشده
به رابط کاربری نشت می‌کرد و کد سخت‌تر خوانده می‌شد. store مبتنی بر context که به‌جای remount مشترکانش را
دوباره رندر کند: قفل لازم نداشت، ولی هر کامپوننت و تابع کمکی‌ای که متن فرمت می‌کند باید subscribe می‌کرد.

**پیامدها.** تغییر متن انگلیسی کلیدش را عوض می‌کند و بررسی CI این را می‌گیرد. مقدارهایی که در زمان اجرا به UI
می‌رسند (برچسب enumها) باید با `msg()` در `format.ts` فهرست شوند. پیام‌های اعتبارسنجی فیلدها از API انگلیسی
می‌مانند. راهنمای یادگیری و مستندات فنی به هر دو زبان وجود دارند، با یک واژه‌نامه‌ی مشترک (`docs/glossary.md`).
