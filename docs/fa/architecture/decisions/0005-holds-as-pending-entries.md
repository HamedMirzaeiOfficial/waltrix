# ADR 0005: رزروها سندهای PENDING تغییرناپذیرند

[English](../../../architecture/decisions/0005-holds-as-pending-entries.md) · **فارسی**

**وضعیت:** پذیرفته‌شده

**زمینه.** یک رزرو (authorization) وجه را الان کنار می‌گذارد و بعداً بخشی یا همه‌ی آن را جابه‌جا می‌کند، یا
هیچ‌وقت. مبلغ رزروشده باید فوراً از موجودی قابل استفاده کم شود، در برابر انتقال‌های هم‌زمان پایدار بماند و
تاریخچه‌ی کامل داشته باشد، در حالی که دفتر روزنامه فقط‌افزودنی می‌ماند.

**تصمیم.** رزرو یک سند تراز با مرحله‌ی `pending` می‌نویسد؛ این سند ستون‌های pending حساب‌ها را تغییر می‌دهد،
نه موجودی ثبت‌شده را. نهایی‌سازی (capture) یک سند **جدید** `posted` می‌نویسد (هر مبلغی تا سقف رزرو) و مبلغ
pending را آزاد می‌کند؛ آزادسازی یا انقضا فقط آن را آزاد می‌کند. خود سند pending هرگز به‌روز نمی‌شود: اینکه
«هنوز حساب می‌شود یا نه» از وضعیت رزرو مشتق می‌شود و reconciliation آن را بررسی می‌کند.

**چرا.** دفتر روزنامه فقط‌افزودنی می‌ماند، موجودی قابل استفاده برابر `posted - pending خروجی` است، و تاریخچه‌ی
کامل یک authorization (درخواست، نهایی‌سازی جزئی، آزاد شدن باقی‌مانده) دیده می‌شود.

**ردشده.** یک ستون `reserved` روی کیف پول بدون سند: ساده‌تر، ولی رزرو هیچ رد حسابرسی‌ای نداشت و reconciliation
نمی‌توانست آن را از نو بسازد. به‌روز کردن سند pending هنگام capture: تغییرناپذیری را می‌شکند و مبلغ اصلی را
گم می‌کند.

**پیامدها.** هر حساب ستون‌های `pending_debits` و `pending_credits` لازم دارد و reconciliation یک بررسی
اختصاصی (`pending_balance_mismatch`) دارد که سندهای pending رزروهای ACTIVE را جمع می‌زند. فقط یک نهایی‌سازی
برای هر رزرو پشتیبانی می‌شود؛ چند نهایی‌سازی جزئی به یک جدول capture نیاز دارد.
